## Manual steps, in order

1. **Rotate the Neon password now.** In the Neon console, reset the role password. Update `DATABASE_URL` in `.env.local` and in every deployment environment.
2. **Stop sharing the database.** Create a Neon branch (for example `dev`) for local work and point `.env.local` at it. Use a separate R2 bucket for dev too. Also remove the duplicate `STORAGE_DRIVER` line in `.env.local`, which currently resolves to `r2`.
3. **Fix `sslmode`** in each `DATABASE_URL` to `sslmode=verify-full`.
4. **Least-privilege role (recommended).** Create an app role with only SELECT/INSERT/UPDATE/DELETE on `public`, use it for the running app, and keep the owner role only for migrations.
5. **Apply migration 0017** against each database, **dev branch first**:
   ```bash
   pnpm db:apply
   ```
   Until it is applied, rate limiting fails open (the site keeps working without limits).
6. **Set new env vars** in the deployment: `CRON_SECRET` (random 32+ bytes), optionally `AI_REQUEST_TIMEOUT_MS` and `RATE_LIMIT_STORE`.
7. **First purge run:** call the cron route with `?dryRun=1` and the bearer header. Check the counts (30 rows were pending at audit time), then let the daily cron run.
8. **On Railway instead of Vercel:** `vercel.json` is ignored there. Schedule a daily HTTP call to the cron route with any scheduler.
9. **Smoke test after deploying:** upload a photo (check background removal and the thumbnail), run analysis, toggle a favourite and reload, edit your name, and try deleting a test account (not your real one) with and without the correct password.
